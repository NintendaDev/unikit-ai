# `direct` — editing a serialized editor file as text

Loaded by Step 3 of `/unikit-execute`, only when `direct` was asked for. `direct` cannot be undone by review — a serialized file edited as text has no preview — so it runs only behind the three gates below, in this order. A gate that fails puts the line back on `manual` with the reason in one line; the run goes on.

1. **The format allows it.** Read `{{skills_dir}}/unikit-plan/references/ENGINE_RULES.md` §6: it owns the table of what may be edited as text and within which bounds. Never use `direct` for a format §6 rates 🔴; for a 🟡 format stay inside the bounds the table names. **If that file is not there**, treat every format as 🔴: refuse `direct`, put the line back on `manual` and state the reason in one line. Continuing silently is not an option — this gate is the only thing standing in front of an edit that review cannot undo. This is not the A9 case: what is missing is not a rule that would grant a right, it is the permission for an irreversible edit.
2. **The rollback point.** Mandatory, and the whole reason the mode is gated — **a rollback point must exist before editing**:
   - files this run changed and has not committed yet → stage only those and commit them: invoke `unikit-commit` (`## Skill calls`), never a `git commit` of your own. The user cancels that commit, or it does not complete → do not edit: put the line back on `manual` and print `WARN [editor] <target>: no pre-edit commit — direct edit skipped, line back on manual`;
   - nothing of this run is uncommitted → `HEAD` already is the rollback point: no commit is needed;
   - the target file itself has uncommitted changes this run did not make — `git status --porcelain -- <target>` shows them and the list taken in Step 1 names the file — a rollback would erase them. Before anything is staged ask once with the question tool of your agent (`AskUserQuestion`): `<target> has uncommitted changes that are not from this run` — `Commit them with the pre-edit commit` / `Leave this line on manual`. The first adds the target to the pre-edit commit; the second puts the line back on `manual` with that reason.
3. **The delegate mode asks nothing and commits nothing**, so it cannot make a rollback point. It runs `direct` only when its hand-off carries a line `Rollback point: <git ref>`, `git rev-parse --verify <ref>` resolves it and the target file has no uncommitted changes. Otherwise the line is returned as `⏸️ MANUAL — no rollback point`.

Once the gates hold, edit the file with `Edit` inside the bounds of §6, then read it back (**A2**): the changed value is read from the file, and through a bridge as well when one is available; the report says how.
