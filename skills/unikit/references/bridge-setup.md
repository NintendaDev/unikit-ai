# Bridge environment check

Runs at Step 11.0 when `.unikit/system/engine-bridges/BRIDGES.md` exists. Read-only probes first; nothing is installed without a confirmation.

For each bridge block, in the file's order:
1. A `probe version` row that holds a command in backticks → run that command; compare its answer with the block's `floor` row when there is one. **How to compare versions:** split each into dotted numbers and compare them as numbers, part by part; a tag after a hyphen puts a version below the same version without it (`0.9.0-exp.1` is below `0.9.0`), and a number inside a tag is a number (`beta.9` is below `beta.14` - never compare the two strings letter by letter). Below the floor, or the command fails → print the rows of the block's `Setup:` table whose `who` is `human` (they are printed, never run). A `probe version` row that tells you to read the MCP settings files is an instruction for the documentation skill and the executors: skip it here.
2. A `probe package` row names a file of the project and a key path in it: read the file with the file-reading tool (no command, no permission), take the value at the key path, and when the file or the key is missing read the fallback the row names. Compare the value with the `floor` row the same way. No value anywhere → the package is not installed: print the `Setup:` row whose `who` is `agent, confirm first` and ask once with the question tool of your agent (`AskUserQuestion`): `Run it now?` — `Run it` · `I will do it myself`. Only on the first answer run it; then say that an editor that is already open loads a new package only after it refreshes the project: bring its window forward and, when Auto Refresh is switched off in the editor, use Assets > Refresh. A value found only in the fallback file means the same thing: requested, not loaded yet.
3. The block has a `status` row → run it once. An error that the block's `Notes:` describe as "the package is in the manifest but the open editor has not loaded it yet" → say the same sentence about refreshing; any other error → print its first line and go on.
4. No probe rows → nothing to check; print the rows of the `Setup:` table once if the bridge has any.

Then the section `Not selected` of `BRIDGES.md`, if it exists: for each row of its table run the command in the `probe` column. It answers → print `A bridge you did not select is available on this machine: <name>. Run unikit-ai init and tick it to register it.` (a late registration goes through init — there is no other command).
