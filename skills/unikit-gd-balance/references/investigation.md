# Investigation — facts for a balance document

Loaded by the open branch, and by ingest when a mismatch between a report and the document has
to be explained. This skill investigates inside itself: there is no separate research step to
hand off to.

## What it may read

**Read-only.** The named slice of the project — `Glob`, `Grep`, `Read`, and `recon-agent` for a
wide question. Facts lifted from code get `provenance: extracted from code`. The GDD and the
code are never edited. The code workspace `.unikit/code/` (plans, code researches) is not
scanned; from it only a document the user named or pasted is read, as a document.

## The extraction engine

`{{skills_dir}}/unikit-gd-recon/references/code-recon.md` — read **only** when facts have to be
lifted from code. If the file is missing, print
`WARN [balance] code-recon reference missing — facts read without the extraction engine; run unikit-ai update`
and continue with your own reading and the same tag.

## Knowledge

The rules `balance`, `economy`, `progression`, `core-loops` from `RULES_INDEX.md`, by their
`Load when`. Methods are cited by rule id; they are never retold inside the document.

## Delegation

The alias in `## Delegation agents` of `SKILL.md`. A wide question goes out as one `recon-agent`
per slice; each is asked "what is measured today, with what, and what needs a tool". The call
itself is written there once and not here.

## Tags on facts

`measured` · `extracted from code` · `decided by user` · `estimate`. A fact with no tag is not
written into `BALANCE.md`.

These four are the balance document's own working vocabulary, not a second provenance system:
`gd-provenance` does not define them, on purpose — a balance document is not a GDD and is not
registered in `GD-IDS.yaml`. `extracted from code` is the **same** tag as in `gd-provenance`
and is written the same way (review holds it at Major or higher); the other three live only in
`BALANCE.md` and `results/` and do not pass into the GDD.

## Conflicts

A conflict "documentation against code or data" goes into the `Unverified and conflicts`
section of `BALANCE.md`. It is not repaired by editing either side.
