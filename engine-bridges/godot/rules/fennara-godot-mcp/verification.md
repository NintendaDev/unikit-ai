## Gate calibration

| gate | reachable | what proves it |
|---|---|---|
| compilation | yes | diagnostics with coordinates, produced as part of the edit that wrote the file. The error count a launch preflight reports is not this gate: it has been measured clean over a project that cannot start |
| console | partly | bound to runs this server started — a cursored log whose increment comes back in the receipt. The editor's own output panel carries no binding to your change |
| structure | yes | the aggregate structural check: strong and precise over the scene it was handed, and covering nothing that scene instances. The tree read is not a second opinion — it folds numbered neighbours away |
| references | yes | the same structural check resolves serialized paths and attached scripts, and names the one that does not resolve |
| behaviour | yes | a live run session with a script inside it: real state, real geometry, real frames — and a start that refuses over a scene whose preconditions fail |
| visual | partly | a frame, by two independent capture routes, and it reaches the agent as an image. There is no baseline and no comparison |

`GATE LIFTED` is not pre-declared here. Unreachability is established by a run:
you tried, the affordance is absent, you produced the evidence of its absence —
only then is the gate lifted, and with a reason.
